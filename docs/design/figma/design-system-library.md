# Figma file 1: Digvation Design System (library)

This is a **separate Figma file**, published as a **Team Library**. The Backoffice and Operational
Figma files enable this library and only use its variables, styles, and components. They never
detach or redraw them.

```text
Digvation Design System (library, published)
├── Digvation Backoffice (product file, uses the library)
└── Digvation Operational (product file, uses the library)
```

The code counterpart is the `@digvation/ui` package (source repo
`dxweb98-sys/digvation-design-system`, consumed here as version `1.1.0`). Every Figma component
in this file maps 1:1 to a `D*` component, and every Figma property maps to a prop with the same
name and values. App-local patterns (shell, page header, KPI card) live in the **Patterns** page
and map to files in this repository.

When this library changes, publish it and accept the update in both product files. When the
change needs code, change `@digvation/ui` first; do not fork a component inside an app.

## 01 Foundations: variables

Import `digvation-tokens.json` (generated by `pnpm design:tokens`) with the **Tokens Studio**
plugin and export it to Figma Variables. You get these collections:

| Collection | Modes                                  | Token set(s)                                      | CSS variable                                          |
| ---------- | -------------------------------------- | ------------------------------------------------- | ----------------------------------------------------- |
| `color`    | `light`, `dark`                        | `mode/light`, `mode/dark`                         | `--color-*`                                           |
| `shadow`   | `light`, `dark`                        | `mode/light`, `mode/dark`                         | `--shadow-*`                                          |
| `radius`   | `soft` (default), `compact`, `rounded` | `radius/soft`, `radius/compact`, `radius/rounded` | `--radius-control`, `--radius-card`, `--radius-panel` |
| `global`   | one mode                               | `global` (spacing, base radius scale, font)       | Tailwind scale                                        |

Rules:

- **Use semantic colors only** (`color/surface`, `color/text-muted`, `color/brand`, …). Raw hex
  values in a product file cannot be mapped back to code.
- `color/brand` is **re-tinted per deployment** at runtime (`runtime-config.json` → `theme`).
  Design with the default blue, but never rely on blue specifically. Brand-on-brand contrast
  must use `color/brand-foreground`.
- Radius presets match `data-theme-radius` (`SOFT`, `COMPACT`, `ROUNDED`). Components use
  `radius/control` (inputs, buttons), `radius/card` (cards), and `radius/panel` (dialogs, menus).
- Spacing follows the 4px Tailwind scale (`spacing/4` = 16px). Use auto-layout gaps and padding
  bound to these variables.

### Responsive grid and breakpoints

Breakpoints are the Tailwind defaults the apps already use (`sm:`, `md:`, `lg:`, `xl:`). Design
**mobile first**: draw the mobile frame, then show what changes at each breakpoint.

| Breakpoint | Min width | Figma frame                                               | Shell behavior (both apps)                    | Content grid                      |
| ---------- | --------- | --------------------------------------------------------- | --------------------------------------------- | --------------------------------- |
| base       | 0         | `Mobile` 390 × 844                                        | No sidebar, mobile navigation, compact header | 4 columns, 16px margin, 12px gap  |
| `sm`       | 640px     | (no own frame)                                            | Same as mobile; two-column forms allowed      | 8 columns, 20px margin, 16px gap  |
| `md`       | 768px     | `Tablet` 834 × 1194 (portrait) and 1194 × 834 (landscape) | Sidebar 232px, header shows date/status       | 8 columns, 24px margin, 16px gap  |
| `lg`       | 1024px    | (covered by tablet landscape)                             | Sidebar 280px                                 | 12 columns, 24px margin, 24px gap |
| `xl`       | 1280px    | `Desktop` 1440 × 900                                      | Sidebar 280px, content max width applies      | 12 columns, 24px margin, 24px gap |

Set these as **layout grid styles** (`grid/mobile`, `grid/tablet`, `grid/desktop`) and apply the
right one to every frame.

Responsive rules every pattern must follow:

- **Tables → cards on mobile.** `DDataTable` keeps its columns from `md` up. Below `md`, show a
  stacked card list (primary text, secondary text, status badge, amount right-aligned, row
  actions in a `Dropdown`). Draw both variants of `Page/ListPage`.
- **Filter bar wraps.** Desktop: one row. Mobile: search full width, filters in a horizontally
  scrollable chip row or behind a "Filter" button that opens a bottom sheet (`Dialog` size
  `full`).
- **Primary action stays reachable.** On mobile the page's primary action moves to a sticky
  bottom bar or a full-width button under the header; never hide it in an overflow menu.
- **Dialogs become sheets.** Below `md`, `Dialog` uses size `full` (full-screen sheet with a
  sticky footer). From `md` up, use the size from the component table.
- **KPI cards** are 1 column (mobile), 2 columns (tablet), 4 columns (desktop).
- **Forms** are 1 column below `sm`, 2 columns from `md` for short fields; long fields span
  the full width.
- **Touch targets:** minimum 44 × 44 on mobile and tablet (Operational is used on tablets at the
  counter). Use `size=lg` buttons and inputs in Operational selling flows.
- **Text never shrinks below** `caption/xs` (12px); truncate with ellipsis and show the full
  value in a tooltip or in the detail view instead.

Use Figma auto layout **Fill / Hug / min-max width** so one component instance resizes across
frames instead of keeping a separate component per breakpoint. Only create a `breakpoint`
variant (`mobile`, `desktop`) when the structure really changes (shell, table vs. cards).

### Icons

The apps use **Lucide** icons (`lucide-react`). Install the Lucide Figma plugin and keep the
layer name equal to the Lucide component name (`ShoppingBag`, `UsersRound`), so the generated
code imports the right icon. Default size 16 (inline) or 20 (navigation), stroke 1.75 to 2.

## 09 Templates

Templates are built only from instances, and **every template exists in three frames**: `Mobile`
(390 × 844), `Tablet` (834 × 1194; Operational also 1194 × 834 landscape), and `Desktop`
(1440 × 900). The product files start every new screen by duplicating one of these:

- `Template/Backoffice/List` (shell + list page)
- `Template/Backoffice/Dashboard` (shell + KPI row + charts grid)
- `Template/Backoffice/Settings` (shell + header + tabs + form sections)
- `Template/Operational/Workspace` (shell + queue bar + catalog grid + cart)
- `Template/Operational/List` (shell + list page)
- `Template/Auth` (login card, used by both apps)

## Connecting to code (Code Connect)

After the components exist, map them with Figma **Code Connect** so Claude Code receives the real
import (`import { DButton } from '@digvation/ui'`) instead of generated markup. Because
`@digvation/ui` lives in its own repository, add the Code Connect files there
(`dxweb98-sys/digvation-design-system`, `packages/ui`) and publish them with
`npx figma connect publish`. Until then, the table above is the mapping Claude Code must follow.

## Definition of done for a library component

- [ ] Auto layout everywhere, no absolute positioning except overlays
- [ ] All fills, strokes, radii, gaps, and padding bound to variables
- [ ] Works in `light` and `dark` mode and in all three radius modes
- [ ] Variant and property names equal the React props
- [ ] Interaction states drawn: hover, pressed, focus (2px `color/focus` ring), disabled, error
- [ ] Text contrast at least 4.5:1 (3:1 for large text and UI borders)
- [ ] Touch targets at least 44 × 44 in Operational usage
- [ ] Resizes correctly from 320px to 1440px wide (Fill/Hug, min/max width), checked in the
      `Mobile`, `Tablet`, and `Desktop` frames
- [ ] Description field filled with the code import path
